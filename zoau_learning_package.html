What is ZOAU?

If you're new to mainframe development, here's the reality: z/OS is powerful but uses older languages (JCL, COBOL, Rexx) for automation. ZOAU bridges that gap by giving Python developers a native interface to z/OS operations.

💡 Think of it as: A universal remote for your mainframe. Control z/OS systems directly from Python instead of wrestling with legacy scripts.

Why Care About ZOAU?

  • Build modern automation using Python (not JCL or Rexx)
  • Reduce manual tasks that waste hours every week
  • Integrate mainframe workflows with cloud/DevOps tools
  • Write cleaner code than legacy scripting languages
  • Enable self-healing systems with automated retries and alerts

The Old Way (Manual + Shell Scripts)

#!/bin/bash # Painful: multiple files, manual parsing, error-prone submit_job.sh sleep 30 poll_status.sh if [[ $status == "COMPLETED" ]]; then extract_spool.sh | grep "SUCCESS" else send_alert.sh fi

The ZOAU Way (Python)

#!/usr/bin/env python3 from zoau import MVSCmd, Jobs # Submit job and wait job = MVSCmd.submit_job(jcl) status = Jobs.wait_for_job(job, timeout=300) # Check result if status == 'CC 0': output = Jobs.get_job_output(job) print(f"Success: {output}") else: send_alert('Job failed', status)
✓ Benefits: One file, natural flow, obvious error handling, testable, maintainable.

    • Module 2: Day 1 Hands-On Guide

    Beginner ⏱️ 30 minutes 🎯 Submit your first job
    ⚡ Goal: By the end of this module, you'll submit a real JCL job from Python and capture the output. No theory. Just working code.

    Part 1: Check Your Environment (5 min)

    Step 1a: Verify z/OS Access

    # From your laptop ssh userid@mainframe.company.com # You should see a z/OS login (USS prompt or ISPF menu) # Type: exit # Back on your laptop

    ✓ What this proves: You have network access to z/OS.

    Step 1b: Check Your Python Version

    python3 --version # Expected output: # Python 3.9.x or newer

    ✓ What this proves: You have a compatible Python runtime.

    Step 1c: Check Your z/OS Credentials

    # In USS on z/OS, try submitting a simple JCL job cat > /tmp/test.jcl << 'EOF' //TESTJOB JOB (ACCT),'TEST',CLASS=A,MSGCLASS=H //STEP1 EXEC PGM=IEFBR14 EOF submit /tmp/test.jcl # You should see a job ID back: # JOB12345 SUBMITTED

    ✓ What this proves: Your account can submit jobs.

    Part 2: Install ZOAU (5 min)

    Step 2a: Install via pip

    pip install zoau # Expected output: # Successfully installed zoau-x.x.x

    Step 2b: Verify Installation

    python3 -c "import zoau; print(zoau.__version__)" # Expected output: # 1.2.3 (or similar version number)

    ✓ What this proves: ZOAU is installed and importable.

    Part 3: Your First Script (10 min)

    Step 3a: Create the Script File

    cat > ~/submit_first_job.py << 'EOF' #!/usr/bin/env python3 """ My first ZOAU script: Submit a simple JCL job """ from zoau import MVSCmd # Define a simple JCL job jcl = """ //MYFIRST JOB (ACCT),'MY FIRST JOB',CLASS=A,MSGCLASS=H //STEP1 EXEC PGM=IEFBR14 """ # Submit the job print("Submitting job...") job_id = MVSCmd.submit_job(jcl) print(f"Job submitted! Job ID: {job_id}") EOF

    Step 3b: Run It

    chmod +x ~/submit_first_job.py python3 ~/submit_first_job.py # Expected output: # Submitting job... # Job submitted! Job ID: JOB12345
    🎉 You just submitted your first job from Python!

    Part 4: Wait & Capture Output

    Enhance the script to wait and check results

    cat > ~/submit_and_wait.py << 'EOF' #!/usr/bin/env python3 from zoau import MVSCmd, Jobs jcl = """ //MYJOB JOB (ACCT),'MY JOB',CLASS=A,MSGCLASS=H //STEP1 EXEC PGM=IEFBR14 """ print("Submitting job...") job_id = MVSCmd.submit_job(jcl) print(f"Job ID: {job_id}") print("Waiting for job to complete...") status = Jobs.wait_for_job(job_id, max_wait_time=300) print(f"Job completed with status: {status}") if status == 'CC 0': print("✓ Success!") else: print(f"⚠ Job did not complete with CC 0. Status: {status}") EOF python3 ~/submit_and_wait.py

    ✓ What this proves: You can submit and monitor a job.

    Module 3: Job Automation & Advanced Patterns

    Intermediate ⏱️ 45 minutes 🎯 Build production pipelines
    💡 What You'll Learn: Retry logic, job pipelines, parallel execution, and production-ready error handling.

    The Problems ZOAU Solves

    Scenario 1: Manual Job Management

    Old Way: 3 AM emergency → SSH to mainframe → check job queue manually → submit recovery job → wait 20 minutes → email the team = 2 hours of your life.

    ZOAU Way: Set it and forget it. Automatic retry. Slack notification. Done in 30 seconds.

    Scenario 2: Multi-Step Dependencies

    Old Way: 12 jobs every Friday. Each depends on previous. One fails? Restart everything manually.

    ZOAU Way: Write once. Chain dependencies. Auto-retry failed steps. Run unattended.

    Lesson 1: Retry Logic (Resilience)

    #!/usr/bin/env python3 def submit_with_retry(jcl_text, max_retries=3, retry_delay=30): """Submit a job with automatic retry on failure""" for attempt in range(1, max_retries + 1): try: print(f"Attempt {attempt}/{max_retries}: Submitting...") job_id = MVSCmd.submit_job(jcl_text) status = Jobs.wait_for_job(job_id, max_wait_time=600) if status == 'CC 0': print(f"✓ Job succeeded on attempt {attempt}") return job_id, status elif status == 'CC 4': # Warning but recoverable return job_id, status else: # Hard failure, retry print(f"✗ Job failed with {status}. Retrying...") if attempt < max_retries: time.sleep(retry_delay) else: raise Exception(f"Job failed after {max_retries} attempts") except Exception as e: print(f"✗ Exception: {e}") if attempt < max_retries: time.sleep(retry_delay) else: raise
    ✓ Real Impact: Transient failures (network glitches, locks) now self-heal automatically. Your 3 AM job doesn't wake you up.

    Lesson 2: Job Pipelines (Orchestration)

    Multi-step workflows where each step depends on the previous one succeeding.

    #!/usr/bin/env python3 def run_pipeline(): """Data pipeline: Extract → Transform → Load → Validate""" jobs = {} # STEP 1: Extract print("[STEP 1] Extracting...") extract_jcl = """//EXTRACT JOB (ACCT),'EXTRACT'...""" jobs['extract'] = MVSCmd.submit_job(extract_jcl) status = Jobs.wait_for_job(jobs['extract'], max_wait_time=300) if status != 'CC 0': print(f"✗ Extract failed: {status}") return False print(f"✓ Extract complete") # STEP 2: Transform print("[STEP 2] Transforming...") transform_jcl = """//TRANSFORM JOB (ACCT),'TRANSFORM'...""" jobs['transform'] = MVSCmd.submit_job(transform_jcl) status = Jobs.wait_for_job(jobs['transform'], max_wait_time=300) if status != 'CC 0': print(f"✗ Transform failed") return False print(f"✓ Transform complete") # STEP 3: Load print("[STEP 3] Loading...") load_jcl = """//LOAD JOB (ACCT),'LOAD'...""" jobs['load'] = MVSCmd.submit_job(load_jcl) status = Jobs.wait_for_job(jobs['load'], max_wait_time=600) if status != 'CC 0': return False print(f"✓ Load complete") return True
    ✓ Impact: Your Friday 12-job sequence now runs unattended, reliably, overnight.

    Lesson 3: Parallel Execution (Speed)

    Run independent jobs simultaneously to cut processing time in half.

    #!/usr/bin/env python3 from concurrent.futures import ThreadPoolExecutor # Without parallelism: 10 jobs × 5 min = 50 minutes # With parallelism: 5 concurrent × 5 min = ~25 minutes with ThreadPoolExecutor(max_workers=5) as executor: futures = { executor.submit(run_job, region): region for region in ['EAST', 'WEST', 'NORTH', 'SOUTH', 'CENTRAL'] } for future in as_completed(futures): region = futures[future] result = future.result() print(f"✓ {region}: {result}")
    ✓ Impact: Daily data processing that took 2 hours now takes 45 minutes.

    Lesson 4: Alerts & Notifications

    Get notified when things break (before your boss calls).

    #!/usr/bin/env python3 def send_slack_alert(message, severity='error'): webhook_url = os.environ.get('SLACK_WEBHOOK_URL') payload = { 'attachments': [{ 'color': 'danger' if severity == 'error' else 'warning', 'title': 'Mainframe Alert', 'text': message }] } requests.post(webhook_url, json=payload) # Use it if status != 'CC 0': send_slack_alert(f"Job {job_id} failed with {status}", severity='error') else: send_slack_alert(f"Job {job_id} succeeded", severity='info')
    ✓ Impact: You sleep. Your automation stays awake and alerts you when needed.

    Module 4: Data Handling - EBCDIC to Pandas

    Intermediate ⏱️ 40 minutes 🎯 Unlock mainframe data for analytics
    ⚡ The Problem: Your mainframe has 50 years of business data. Your analytics tools speak Python/pandas. They don't understand each other. ZOAU is the bridge.

    Understanding the Gap: EBCDIC vs ASCII

    What's EBCDIC?

    EBCDIC (Extended Binary Coded Decimal Interchange Code) is how mainframes store text.

    Mainframe data: c7 93 96 84 (EBCDIC bytes) What it means: G O O D (ASCII text) What you see: ☒ ☓ ☓ ← (gibberish if you don't decode)
    📌 Why It Matters: If you read mainframe data without converting it, you get garbage. Pandas can't analyze garbage.

    Step 1: Read Mainframe Data

    from zoau import Datasets from zoau.encoding import ebcdic_to_ascii dataset_name = 'MYUSER.CUSTOMER.DATA' # Read raw EBCDIC records raw_records = Datasets.read(dataset_name) print(f"Read {len(raw_records)} records") print(f"First record (raw): {raw_records[0]}") # Looks like garbage

    ✓ Result: Raw EBCDIC bytes. Not human-readable yet.

    Step 2: Understand Record Layout

    Mainframe datasets have fixed-width records. You need to know the layout.

    # Example: Customer dataset layout RECORD_LAYOUT = { 'customer_id': (0, 10), # bytes 0-10 'name': (10, 40), # bytes 10-40 'phone': (40, 50), # bytes 40-50 'email': (50, 70), # bytes 50-70 'status': (70, 80) # bytes 70-80 }
    💡 Tip: Ask your mainframe team for the COBOL copybook. It defines these exact positions.

    Step 3: Convert & Parse Data

    #!/usr/bin/env python3 from zoau import Datasets from zoau.encoding import ebcdic_to_ascii import pandas as pd RECORD_LAYOUT = { 'customer_id': (0, 10), 'name': (10, 40), 'phone': (40, 50), 'email': (50, 70), 'status': (70, 80) } # Read raw data raw_records = Datasets.read('MYUSER.CUSTOMER.DATA') # Convert and parse parsed_records = [] for raw_record in raw_records: # Convert EBCDIC → ASCII ascii_record = ebcdic_to_ascii(raw_record) # Parse fixed-width fields parsed = {} for field_name, (start, end) in RECORD_LAYOUT.items(): value = ascii_record[start:end].strip() parsed[field_name] = value parsed_records.append(parsed) # Load into pandas df = pd.DataFrame(parsed_records) print(df.head())
    ✓ You now have a pandas DataFrame with readable data!

    Step 4: Clean & Validate Data

    #!/usr/bin/env python3 import pandas as pd # ... [previous code to load data into df] ... # Cleaning steps df['name'] = df['name'].str.strip().str.title() df['email'] = df['email'].str.strip().str.lower() df['status'] = df['status'].replace({'A': 'Active', 'I': 'Inactive'}) # Remove invalid records df = df[df['email'].str.contains('@', na=False)] # Print summary print(f"Total records: {len(df)}") print(f"Status breakdown:\n{df['status'].value_counts()}")

    ✓ Result: Clean, standardized data ready for analysis.

    Step 5: Analyze & Export

    Basic Analytics

    # Analyze active_pct = (df['status'] == 'Active').sum() / len(df) * 100 print(f"Active customers: {active_pct:.1f}%") # Email domains df['domain'] = df['email'].str.extract(r'@(.+)$') print(df['domain'].value_counts().head(10))

    Export to Multiple Formats

    # CSV (Excel-friendly) df.to_csv('customers.csv', index=False) # JSON (APIs) df.to_json('customers.json', orient='records') # Parquet (big data) df.to_parquet('customers.parquet', index=False) # Cloud (BigQuery, S3, etc.) # See Module 4 extended content for cloud integration
    ✓ Your mainframe data is now in modern formats, ready for analytics and cloud.

    When You Get Stuck

    🆘 Common Issues:
    • EBCDIC conversion errors: Check record length matches expected layout
    • Job timeout: Increase max_wait_time or check job queue depth
    • Dataset not found: Verify dataset exists with tsocmd "LISTCAT"
    • Permission denied: Ask mainframe admin for JCL submit rights
    • Memory errors: Process data in chunks instead of all at once
